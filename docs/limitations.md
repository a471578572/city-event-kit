# 使用边界

City Event Kit 适合有现场工作人员的小型评比活动。它帮助组织名单、展示流程和保存结果，不替代主办方的资格审核、评审制度或身份核对。

## 手机号是入场标识，没有短信验证

当前输入登记手机号即可使用对应选手或观众身份。没有验证码、密码或手机号所有权证明。知道他人登记号码的人可能进入其身份；跨设备登录也不会增加验证步骤。

评委使用共享的本场专用入口，再选择本人姓名。这个入口也应按私密资料发放，程序不单独证明姓名使用者就是评委本人。

工作人员应在现场处理错填和冒用。要用于高价值奖金、远程开放比赛或必须实名的场景，需要另行设计可靠身份验证、异常处理和申诉流程。

## 一人一票权依赖登记与现场管理

程序按身份保存票权，换设备不会生成新票权，重复提交不会增加票数，同一设备也不能创建多个新观众身份。但这些限制不能证明“一个自然人只有一个手机号”，不能作为完整的防刷票机制。

人气投票提交后不可修改；开放期间评委可修改评分。管理员可以控制阶段、维护允许修改的名单、处理同分和重置登录入口，因此管理员及其凭据必须可信。

## 数据保存在运行服务的机器

默认本地服务采用 SQLite 文件保存数据，单进程运行。关闭服务后暂停访问，重启同一数据目录会继续使用原数据。项目不自动提供云同步、多区域容灾、共享限流或多实例部署。

Docker 容器必须挂载持久数据卷。没有持久卷时重建容器可能丢失数据。程序中的请求限制为单实例限制，不等同于外部流量防护。

当前程序校验上限为 100 支队伍、100 位评委、2,000 位选手与观众合计；单次选手导入最多 500 人。这些是输入限制，不代表已经完成对应人数同时在线的容量测试。实际规模需要在自己的部署环境中验证。

## 公开与私密资料分开保管

公开选手墙默认关闭。完整备份、数据库、管理员入口和个人身份凭据属于私密资料，不应提交到 Git 或放入静态网站。

公网部署由使用者配置有效 HTTPS、域名、反向代理及服务器访问权限。Docker 文件本身不提供 HTTPS，也不意味着服务已经适合直接公开。

## 测试通过不等于现场已验收

自动测试使用虚构资料验证规则和接口，不证明所有手机、网络、打印机或现场流程都可用。正式活动前仍需用实际访问地址、手机和投影设备走一遍流程，并核对备份能否在独立目录中恢复。

本项目不宣称已经通过外部安全审计，不承诺无故障或适用于任何规模。发现问题可按 [贡献说明](../CONTRIBUTING.md) 提供去除个人资料的复现；涉及权限或泄露的问题按 [安全说明](../SECURITY.md) 私下处理。
