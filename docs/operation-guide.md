# 现场操作手册

这份手册适用于准备、演练、正式评分与投票、截止核对、公布结果五个阶段。工作人员保管管理员入口；参加者只收到其身份需要的入口。

## 1. 准备活动与名单

首次启动正式服务前，先按 [配置说明](customization.md) 填写活动名、城市、日期与链接，并为本场活动选用新的数据目录。完成后再启动服务，在活动主页或活动指引点击“组织者后台”。用文本编辑器打开这份服务生成的 `data/admin.key`，复制完整管理密钥并输入；也可以直接打开 `data/admin-entry.html`，使用其中的私密入口。首次启动应没有任何选手、队伍、评委、评分或投票。

管理密钥及私密入口文件只能交给可信工作人员，不要发到活动群。参加者无需管理密钥；主页有后台入口也不代表任何访客都能管理活动。

1. 在“比赛设置”的“1. 导入选手名单”中导入选手，核对姓名和手机号。先处理错误和冲突，再确认导入。
2. 在“2. 导入队伍名单”中导入队伍，确保队长和所有队员已登记为选手，每队含队长最多 4 人。
3. 在“3. 编辑评委名单”中导入或维护评委。评委姓名应能让本人准确识别；数量由本场活动决定。
4. 决定是否开放观众自助登记与投票，以及选手能否继续组队。
5. 核对后台的队伍、作品、成员与评委信息，保存一份私密备份。

不要用真实活动资料做公开问题反馈。三类 CSV 模板和填写方式见 [examples](../examples/README.md)。

## 2. 先演练，再切回正式环境

`npm run demo` 使用 `data-demo/` 的虚构资料。演练时分别用选手、观众和评委身份，完成一次从入场到公布结果的流程。

演练完成后停止演示服务，再启动正式服务。检查管理员入口来自 `data/`，页面显示的是实际活动，名单中没有“选手甲”“示例一队”等演示记录。正式活动开始后请保持服务运行。

## 3. 发放入口

在“入口发放”中取得本场二维码与链接：

- **选手公共入口**：选手输入已经登记的手机号，进入自己的身份。
- **观众公共入口**：只有启用观众自助登记时，新观众才能填写称呼与手机号登记。
- **评委专用入口**：仅发给本场评委，由本人选择姓名进入。不要放进公共群或公开投影。
- **管理员入口**：只交给可信工作人员，不转成公开报名码。

手机号入场没有短信验证，工作人员应在现场处理错填、重名和冒用问题。换手机或浏览器不需要重置身份，已有身份会继续使用原队伍、票权、评分和投票记录。已登记的人可跨设备登录；同一设备仍不能连续创建多个新观众身份。

用实际手机访问正式 HTTPS 地址。确认至少一个选手入口和一个评委入口可打开，服务端确实保存了演练提交，再发放给全场。手机无法访问电脑自己的 `localhost`。

## 4. 路演与开放评比

“路演抽签”用于安排展示顺序。抽签或调整后核对完整名单，再展示公开顺序页。路演顺序不会改变评分权重或票数。

确认名单、评委和规则后，点击开放评比。开放期间：

- 评委按四项标准评分。页面草稿不计入结果，点击提交并收到保存确认后才算已交；截止前可修改。
- 有利益关系的评委应声明回避。手动回避会删除其对该队已有的评分，不能自行撤销。兼任选手的评委对本队自动回避。
- 选手每人最多投 3 支其他队伍，观众每人最多投 2 支队伍；允许少投，每队最多 1 票。
- 人气票提交后不可修改。刷新、换设备或重复点击不会产生额外票权；以页面显示的已保存回执为准。
- 未组队选手应先完成组队再投票。已有评分或人气票关联的队伍，以及已投票选手的换队操作，受程序限制。

在“评分进度”核对每位评委的提交情况和总票数。提交出现“未能确认”时先刷新查看记录，不要假定失败后立即反复操作。

## 5. 截止并核对

宣布截止后，点击“截止评分与投票”。随后：

1. 检查是否仍有应交但未交的评分，以及是否出现全体评委均回避的队伍。
2. 检查回避原因，确认没有用零分代替缺交或回避。
3. 对影响名次的评委同分进行现场合议，在“结果与导出”记录顺序、依据和参与确认人员。
4. 人气同票按本场事先说明的方式处理；未确认时保留“待定”，不要自行补票。
5. 导出成绩表并保存完整私密备份，交由另一位工作人员复核。

重新开放会允许评委继续修改和未投票者提交，但不会让已投票者重投；之前的同分合议会清除，需要重新核对。它不等同于清空或重办一场活动。

## 6. 公布与归档

评委评分齐全且必要合议完成后，点击“公布结果”。核对公开页上的队伍、作品、名次及人气奖状态，再制作通用证书。

通用证书不带任何现实组织的授权素材。填写颁发方前，由主办方确认名称、结果和使用权限。实际打印与盖章由主办方完成。

成绩 CSV 用于结果归档；完整备份包含手机号、报名资料和登录凭据，仅供工作人员保存。详细内容与迁移方式见 [数据与备份](data-and-backups.md)。
