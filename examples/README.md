# 虚构示例名单

这些文件只用于演示和检查导入流程，不含真实报名资料。所有人物、队伍及作品都是虚构的。`19900000001` 至 `19900000008` 只是符合程序格式的模拟号码，不代表运营商保留号段，请勿拨打或发送短信。

在演示环境中按以下顺序导入：

1. `players.csv`：8 位选手。
2. `teams.csv`：4 支队伍，每队 2 人；队长已经包含在这 2 人中。
3. `judges.csv`：3 位评委。实际活动的评委数量由管理员维护，示例的 3 人不是固定人数。

正式活动请先停止演示，使用独立的空数据目录，再导入实际名单。

## CSV 格式

使用 UTF-8 编码，保留第一行表头。Excel 或其他表格工具导出时选择“CSV UTF-8”，把手机号列设为文本，避免科学计数法。带英文逗号或换行的单元格需使用标准 CSV 引号。

### 选手

```csv
姓名,手机号,背景,参与方式,创作方向,擅长,AI经验
选手甲,19900000001,虚构设计背景,现场组队,游戏,视觉设计,初次体验
```

姓名和手机号用于建立选手身份，其余列用于报名资料。导入前核对预览中的人数、重复项和错误项。手机号是当前身份识别依据，修改号码应当作身份维护处理，不能用换号方式给同一人增加票权。

示例不需要“状态”列。如果从报名工具导出的 CSV 带有状态列，只会导入标记为“已通过”的记录；先在预览中确认被排除的人数是否符合预期。

### 队伍

```csv
队伍名称,作品名称,赛道,队长手机号,队员手机号
示例一队,虚构街区小游戏,game,19900000001,19900000002|19900000003
```

先导入选手。队长手机号单独填写；“队员手机号”填写其他成员，多人用英文竖线 `|` 分隔。每队包括队长在内最多 4 人，一个选手只属于一支队伍。没有其他成员时最后一列留空。

示例采用程序接受的赛道值：

| 值 | 对应方向 |
| --- | --- |
| `dining` | 餐饮 |
| `detective` | 推理 |
| `office` | 办公 |
| `short-drama` | 短剧 |
| `opc` | 一人公司 |
| `game` | 游戏 |

赛道不改变评分权重或票权。调整赛道选项属于代码定制，见 [配置说明](../docs/customization.md)。

### 评委

```csv
姓名,介绍
评委甲,虚构评委；关注完成度与可用性
```

评委姓名应当便于本人识别。评委使用工作人员单独发放的评委入口；不要把评委入口发布到公共活动群。
