# City Event Kit · 城市活动现场评比工具

给城市社群、创作营和小型比赛使用的现场工具：导入选手与队伍，发放入场二维码，安排路演，收集评委评分和人气票，再核对、导出并公布结果。

代码采用 [MIT 许可](LICENSE)。仓库提供通用页面和虚构示例，不包含真实活动名单、组织标志或原活动海报、证书素材。

> 当前手机号入场**没有短信验证**，适合工作人员能现场核对身份的低门槛活动。知道登记手机号的人可能进入对应身份；评委入口也需要单独保管。它不适合直接作为高价值奖励、远程实名投票或强身份认证系统。详见 [使用边界](docs/limitations.md)。

## 现在可以做什么

- 分别导入选手、队伍、评委 CSV，或在后台维护名单。
- 让选手与观众通过手机号入场，换手机或浏览器后继续使用原身份与已提交记录。
- 让选手创建、加入队伍，查看队伍和路演顺序。
- 按四项标准收集评委评分，记录利益回避及同分合议。
- 收集选手和观众的人气票，提交后保留投票回执。
- 导出成绩表与完整私密备份，使用通用证书模板。
- 修改城市、活动名、日期、标志、报名及手册链接；公开选手墙默认关闭。

首版用 Node.js 标准库 SQLite 保存数据，不需要购买数据库服务，也没有必装的 npm 运行依赖。正式启动时名单、评分和投票均为空；演示数据使用独立目录。

## 快速开始

### 1. 下载并运行

安装 **Node.js 22.13 或更新版本，推荐 Node.js 24**，再选择取得项目的方式：

- **保留自己的版本**：[使用 GitHub 模板创建仓库](https://github.com/a471578572/city-event-kit/generate)，之后在自己的仓库点击 **Code → Download ZIP** 下载。
- **直接运行**：[下载最新发布包](https://github.com/a471578572/city-event-kit/releases/latest)，选择发布附件中的 `city-event-kit-版本号.zip`，并保留随附的 `.sha256` 校验文件。

解压后进入含 `package.json` 的项目文件夹。正式使用前先按下节填写 `web/site-config.json`，再在终端运行：

```sh
node --version
npm start
```

保持这个终端运行。首次启动会创建 `data/`。组织者有两种进入后台的方式：

- 在活动主页或活动指引点击 **“组织者后台”**，用文本编辑器打开自己服务的 `data/admin.key`，复制完整管理密钥并输入。
- 用浏览器打开 `data/admin-entry.html`，点击其中的私密管理入口。

后台入口需要管理密钥验证身份。`admin.key` 和 `admin-entry.html` 都只交给可信工作人员，不要群发、放进公开网盘或提交到 GitHub。页面中不会展示或提供他人的管理密钥。

电脑上的服务停止后，页面无法继续读写；数据保存在 `data/`，重新启动同一目录会继续使用原数据。首次使用先在本机走完整个演示流程，再部署供手机访问。

### 2. 设置自己的活动

编辑 [`web/site-config.json`](web/site-config.json)，填写活动名称、城市、日期及其他公开信息。标志文件放入 `web/assets/`，再在配置中填写路径。详见 [配置自己的活动](docs/customization.md)。

### 3. 按顺序导入名单

在后台先导入**选手**，再导入**队伍**，最后导入**评委**。每次先检查导入预览，再确认保存。队长和队员的手机号必须已经存在于选手名单中。

[`examples/`](examples/README.md) 提供三种 CSV 模板。它们都是虚构演示资料，正式活动请替换为已确认的实际名单。

### 4. 演练后再正式开放

想先体验完整流程，停止当前服务后运行：

```sh
npm run demo
```

演示使用 `data-demo/`，不会把演示人物加入 `data/`。从演示的私密管理员入口检查选手入场、评委评分、投票回执、截止和公布结果。

**正式开始前停止演示，重新运行 `npm start`，核对当前活动名称与真实名单。** 不要在演示库中继续录入正式比赛，也不要把演示二维码发给参加者。

按 [现场操作手册](docs/operation-guide.md) 发放公共入场码和评委专用入口，核对手机能打开页面后再开放评分与投票。要给外部手机使用，按 [部署说明](docs/deployment.md) 配置自己的 HTTPS 地址；本机 `localhost` 地址只用于当前电脑。

## 首版规则

| 项目 | 规则 |
| --- | --- |
| 评委评分 | 完成度与可用性 30%、创意 25%、场景价值 25%、展示 20% |
| 单项分值 | 0—10 分，可填一位小数 |
| 队伍得分 | 未回避评委的加权分取平均；缺交不按零分处理 |
| 选手人气票 | 每人最多 3 票，每队最多 1 票，不能投本队 |
| 观众人气票 | 每人最多 2 票，每队最多 1 票 |
| 提交后 | 人气票不可修改；评委评分在开放期间可修改 |
| 队伍人数 | 包括队长在内最多 4 人 |
| 同分 | 需要时由现场合议，管理员记录顺序和依据 |

评分权重、票数及人数上限是首版代码规则，后台没有任意改权重功能。评委人数可以在准备阶段维护，范围为 1—100 人，不固定为示例的 3 人。调整规则时需同步修改校验、页面、说明和测试。

## 检查与打包

```sh
npm test
npm run check:privacy
npm run package
```

自动检查验证程序行为与分发内容；它们不能替代活动场地的手机网络、投影、打印和人工身份核对。活动前请使用实际访问地址完成一次演练。
