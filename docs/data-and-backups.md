# 数据与备份

数据是否保存成功，以服务端返回确认、刷新后仍能读到记录为准。页面草稿、截图或下载了一份空文件都不等于完成备份。

## 哪些内容需要保管

| 内容 | 用途与边界 |
| --- | --- |
| `data/` | 正式运行数据与管理员资料；应整体私密保管 |
| `data/event.sqlite3` | SQLite 活动数据库；可能同时存在配套日志文件 |
| `data/admin.key` | 管理密钥，可用于主页“组织者后台”登录；不能公开、群发或随意删除 |
| `data-demo/` | 独立演示数据，不用于正式结果 |
| `admin-entry.html` | 管理员私密入口；持有者可能控制活动 |
| 后台导出的成绩 CSV | 结果归档，可按活动公开范围分享；不能恢复整个活动 |
| 后台导出的完整 JSON 备份 | 含名单、手机号、报名资料、身份凭据、评分、投票等状态；只交给可信工作人员 |
| `web/site-config.json` 与 `web/assets/` | 公开配置与自己的素材，需另外保存 |

Git 忽略规则和打包检查只是防止误带出的辅助措施。使用自定义目录、重命名文件或另行上传时，仍需人工确认内容。完整备份不自动脱敏，也不自动加密。

## 活动中导出

在后台“结果与导出”点击“保存完整备份”。下载后确认文件大小合理，并在自己的可信机器上运行校验：

```sh
node cloud/validate-backup.mjs /path/to/private-backup.json
```

把 `/path/to/private-backup.json` 替换为自己的实际文件路径。含空格的路径要加引号。校验只验证备份格式及活动规则，不会导入、修复或覆盖当前活动，也不证明其中的人员信息已经人工核实。

活动准备完毕、正式截止后、结果公布后各保存一份，文件名记录时间与阶段。成绩 CSV 另行保存，便于核对和交接。

## 保存完整本地快照

需要迁移机器或保留可直接重新运行的副本时，先停止服务，再复制整个数据目录。SQLite 可能有配套日志文件，运行中只复制一个数据库文件不一定得到一致副本。

本机操作顺序：

1. 在运行服务的终端按 `Ctrl+C`，确认进程退出。
2. 把整个 `data/` 复制到私密备份位置，使用新的目录名，不覆盖上一次备份。
3. 另存本次使用的程序版本、`web/site-config.json` 和自有素材。
4. 重新运行 `npm start`，刷新后台核对阶段和人数。

Docker 可以在停止容器后复制数据目录。以下示例的目标目录必须是新的：

```sh
docker stop city-event-kit
mkdir -p backups
docker cp city-event-kit:/app/data ./backups/data-snapshot
docker start city-event-kit
```

这会复制私密资料。限制 `backups/` 的访问权限，不要将其发布到网站或云盘公开链接。不要删除正在使用的数据卷。

## 恢复与迁移

先在独立目录检查，不直接覆盖仍在运行的正式数据。

如果有停止服务后保存的完整数据目录，可以复制成 `data-restored/`，然后在没有其他本实例运行时启动：

```sh
DATA_DIR=./data-restored npm start
```

上述写法适用于 macOS/Linux shell；其他环境可在 `.env` 中设置 `DATA_DIR`，使用部署说明中的启动命令。打开恢复目录内生成的私密管理员入口，核对以下内容：

- 活动名称、阶段、选手、队伍及评委人数。
- 已有评分、回避、人气票和同分处理记录。
- 导出的成绩与原备份时一致。
- 公开地址正确，参加者入口指向准备使用的服务。

文件快照和 JSON 备份不是同一种恢复方式。不要把 JSON 文件直接改名为数据库或放入 `data/` 就当作恢复完成。恢复后的数据、凭据与对外入口都应重新核对。

**首版没有在线恢复按钮，也没有导入 JSON 备份的恢复命令。** `validate-backup.mjs` 只读校验。当前可直接迁移的是停止服务后保存的完整数据目录；只有 JSON 备份时，需要由熟悉该版本数据格式的维护者另外处理，不能承诺一键恢复。

## 管理员与身份凭据

管理员入口、数据目录和 `.env` 不应放入公开版本库。备份中的个人身份凭据同样可以用于访问对应身份。

参加者换设备不需要重置登录；只有处理入口泄露或身份问题时，才在当面核对后使用后台重置功能。重置会让旧个人凭据失效，保留其队伍、评分和投票记录。

管理员凭据的更换涉及服务配置以及评委专用入口。由部署负责人先备份、停止服务，再按实际配置更换并重新发放必要入口。不要在不知道文件用途时删除整个数据目录。
