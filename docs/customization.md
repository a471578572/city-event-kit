# 配置自己的活动

公开的活动信息放在 `web/site-config.json`。**首次启动正式服务前先确定活动名、城市和日期。** 保留合法 JSON 格式；最后一项后面不要加逗号。

程序在启动时读取一次配置，修改后需要重启。首次创建数据目录时，活动名称会写入数据库；已有数据库中的活动名称不会因修改 `name` 或重启而自动改写。请核对后台与公共页面的名称一致，不要把改配置当作更名或清空旧活动。

**每场新活动使用新的 `DATA_DIR`。** 已经开始评分的活动不要替换成另一场活动的配置；先归档原活动，再为新活动准备独立数据目录。更改 `PUBLIC_ORIGIN` 后，重启会重新生成私密管理员入口，发放前还需核对二维码的实际访问地址。

```json
{
  "name": "示例城市创作会",
  "city": "示例城市",
  "date": "2026-11-01",
  "subtitle": "一起把想法做成作品",
  "logos": [{ "name": "活动标志", "src": "assets/event-mark.svg" }],
  "registrationUrl": "",
  "handbookUrl": "",
  "publicPlayerWall": false,
  "certificateIssuer": "示例活动组委会"
}
```

这里的名称和日期仅展示填写格式，不代表已经举办或确认的活动。

| 字段 | 用途 |
| --- | --- |
| `name` | 公开活动名称 |
| `city` | 城市名称 |
| `date` | 公开活动日期；必须是有效的 `YYYY-MM-DD` 日期 |
| `subtitle` | 简短活动说明 |
| `logos` | 1—30 个标志，每项包含 `name` 和 `src`；可先保留自带通用标志 |
| `registrationUrl` | 公开报名地址；不需要时留空字符串 |
| `handbookUrl` | 参加者手册地址；不需要时留空字符串 |
| `publicPlayerWall` | 是否启用公开选手墙；默认 `false` |
| `certificateIssuer` | 通用证书显示的颁发方 |

这些配置会公开给访问者。不要在里面填写管理员入口、评委私密入口、个人手机号、访问密钥或内部资料链接。

## 加入自己的标志

1. 把已经取得使用权限的文件放入 `web/assets/`，例如 `web/assets/organizer.svg`。
2. 在 `logos` 中填写相对于网站目录的地址：

```json
"logos": [
  { "name": "示例主办方", "src": "assets/organizer.svg" },
  { "name": "示例协作方", "src": "assets/partner.png" }
]
```

3. 刷新页面，分别检查手机和桌面下是否清晰、完整。上述文件名只是格式示例，仓库不会附带现实组织标志。

不要用网络上找到的组织标志暗示合作或背书。MIT 许可允许使用代码，不会授予组织名称、商标或外部素材的使用权。

## 公开选手墙

默认关闭。只有参加者清楚知道将展示哪些资料，并同意公开后，才考虑将 `publicPlayerWall` 改为 `true`。开放前以未登录的访客身份检查实际页面，确认只展示适合公开的信息。

选手墙是公开展示功能，不是私密通讯录。即使未来再次关闭，已经被访问、截图或转发的资料也不会自动撤回。

## 证书

首版提供原创通用版式。核对活动名、颁发方、获奖人或队伍、奖项与日期后再使用。它不附带现实组织的印章、授权或认证效力。

## 需要改代码的部分

首版固定四项评分及权重、选手与观众票数、每队人数上限和赛道选项。后台支持名单和活动流程维护，不提供任意修改这些规则的编辑器。

要调整规则，应同步修改后端校验、前端说明、导入字段、结果计算和相应测试，并使用独立演示数据重新演练。不要只修改页面上的数字。开发方式见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
